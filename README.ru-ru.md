# LeetCode на Haskell

![CI](https://github.com/AF2B/Leetcode/actions/workflows/ci.yml/badge.svg)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)
![Haskell](https://img.shields.io/badge/Haskell-GHC%209.10-blue.svg)

Коллекция решений задач LeetCode, написанных полностью на Haskell. Одна и та же задача часто решается несколькими способами — оптимальный подход, полный перебор, дизайн на основе тайпклассов и классические паттерны проектирования, закодированные средствами системы типов Haskell — с автоматической проверкой сборки, статического анализа, форматирования и тестов при каждом pull request.

## Зачем несколько подходов к одной задаче

Решить задачу один раз — значит доказать, что ответ найден. Решить её ещё раз как базовый вариант полным перебором, ещё раз через чистую композицию на основе тайпклассов и ещё раз через классический паттерн проектирования — значит доказать, что вы понимаете, *почему* ответ работает, а заодно оставить справочник о том, как одна и та же идея выглядит при разных ограничениях.

## Структура репозитория

```
solutions/
  R0001_0100/
    P0001_TwoSum/
      README.md            # краткое условие, теги, сложность по каждому подходу
      Optimized/
        Solution.hs
        SolutionSpec.hs
      BruteForce/
      Functional/
      DesignPatterns/
  R0101_0200/
    ...
```

Задачи сгруппированы диапазонами по 100, чтобы репозиторий оставался удобным для просмотра даже после задачи №3000. Имена папок одновременно являются компонентами имени модуля Haskell, поэтому используются сегменты в `PascalCase`/`Snake_Case` вместо дефисов, которые использует сам LeetCode в своих слагах. В каждой папке задачи описана временная и пространственная сложность каждого подхода. Обязательна только папка `Optimized/` — остальные подходы добавляются постепенно. `hspec-discover` автоматически находит каждый файл `*Spec.hs` внутри `solutions/`, поэтому тесты новой задачи запускаются в CI без ручной регистрации.

Задачи по SQL не имеют осмысленного эквивалента на Haskell (LeetCode ожидает SQL-запрос, а не программу), поэтому папка `sql/` остаётся без изменений и не входит в область миграции на Haskell.

## Сборка и тесты локально

Требования: GHC ≥ 9.10 и Cabal ≥ 3.16 (установка через [ghcup](https://www.haskell.org/ghcup/) покрывает оба), а также [hpack](https://github.com/sol/hpack).

```bash
hpack
cabal build --enable-tests
cabal test
```

## Непрерывная интеграция

При каждом pull request выполняются три проверки:

1. **Сборка и тесты** — `cabal build`/`cabal test` для каждого решения и его спецификации Hspec.
2. **Статический анализ** — `hlint`.
3. **Проверка форматирования** — `fourmolu --mode check`.

## Прогресс

🚧 Репозиторий находится в процессе миграции на Haskell. Решения, ранее написанные на других языках, переводятся по одному pull request за раз.
