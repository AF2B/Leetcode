# LeetCode на C++

![CI](https://github.com/AF2B/Leetcode/actions/workflows/ci.yml/badge.svg)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)
![C++23](https://img.shields.io/badge/C%2B%2B-23-blue.svg)

Коллекция решений задач LeetCode, написанных полностью на современном C++ (C++23). Одна и та же задача часто решается несколькими способами — оптимальный подход, полный перебор, объектно-ориентированный дизайн, функциональный стиль и классические паттерны проектирования — с автоматической проверкой сборки, статического анализа, форматирования и тестов при каждом pull request.

## Зачем несколько подходов к одной задаче

Решить задачу один раз — значит доказать, что ответ найден. Решить её ещё раз через иерархию классов, ещё раз с `std::ranges` без изменяемого состояния и ещё раз через паттерн проектирования — значит доказать, что вы понимаете, *почему* ответ работает, а заодно оставить справочник о том, как одна и та же идея выглядит при разных ограничениях.

## Структура репозитория

```
solutions/
  0001-0100/
    0001-two-sum/
      README.md            # краткое условие, теги, сложность по каждому подходу
      optimized/
        solution.hpp
        solution.cpp
        test.cpp
      brute-force/
      oop/
      functional/
      design-patterns/
  0101-0200/
    ...
```

Задачи сгруппированы диапазонами по 100, чтобы репозиторий оставался удобным для просмотра даже после задачи №3000. В каждой папке задачи описана временная и пространственная сложность каждого подхода. Обязательна только папка `optimized/` — остальные подходы добавляются постепенно.

Задачи по SQL не имеют осмысленного эквивалента на C++ (LeetCode ожидает SQL-запрос, а не программу), поэтому папка `sql/` остаётся без изменений и не входит в область миграции на C++.

## Сборка и тесты локально

Требования: CMake ≥ 3.20 и компилятор с поддержкой C++23 (GCC ≥ 13 или Clang ≥ 16).

```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

## Непрерывная интеграция

При каждом pull request выполняются три проверки:

1. **Сборка** — компиляция каждого решения с флагами `-Wall -Wextra -Wpedantic -Werror`.
2. **Статический анализ** — `clang-tidy` и `cppcheck`.
3. **Проверка форматирования** — `clang-format --dry-run --Werror`.
