# LeetCode на C++

![CI](https://github.com/AF2B/Leetcode/actions/workflows/ci.yml/badge.svg)
![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)
![C++23](https://img.shields.io/badge/C%2B%2B-23-blue.svg)

Коллекция решений задач LeetCode, полностью написанных на C++23. Каждая
решённая задача сопровождается автоматическим модульным тестом, а одна и та
же задача часто решается более чем одним способом — грубой силой,
оптимизированно, рекурсивно и так далее — все варианты сосуществуют в одних
и тех же файлах, с автоматическими проверками сборки, статического анализа и
форматирования при каждом pull request.

## Зачем несколько подходов к одной задаче

Решить задачу один раз — доказательство того, что вы нашли ответ. Решить её
ещё раз через грубую силу, ещё раз в оптимизированном варианте, ещё раз
рекурсивно (или любым другим возможным способом) — доказательство того, что
вы понимаете, *почему* ответ работает, и оставляет ориентир для того, как
одна и та же идея выглядит при разных ограничениях. Это не обязательное
требование для каждой задачи, но структура готова к этому всегда, когда это
того стоит.

## Структура репозитория

```
solutions/
  0001-0100/
    0001-two-sum/
      README.md         # описание условия, ссылка, сложность, теги
      solution.hpp       # публичный интерфейс — одна функция на подход
      solution.cpp       # реализация
      test.cpp           # тесты Catch2 — один TEST_CASE на подход
  0101-0200/
    ...
```

Задачи группируются диапазонами по 100, чтобы репозиторий оставался удобным
для просмотра и после задачи #3000. Каждая задача — это одна папка ровно с
тремя файлами кода — никогда не папка на каждый подход: если задача решена
несколькими способами, каждый подход — это отдельная функция (или метод) в
одних и тех же `solution.hpp`/`solution.cpp`, покрытая своим `TEST_CASE` в
одном и том же `test.cpp`. `README.md` задачи описывает саму задачу (краткое
условие, ссылку, сложность, теги), а не подходы — они документируются
комментариями в коде.

Каждая задача обязана иметь тест — решение без `test.cpp`, покрывающего его,
не считается завершённым.

Задачи по SQL не имеют осмысленного эквивалента на C++ (LeetCode ожидает SQL-
запрос, а не программу), поэтому устаревшая папка `sql/` остаётся как есть и
не входит в область этой миграции.

## Соглашение о коммитах

Каждый коммит помечается эмодзи, описывающим его назначение:

| Эмодзи | Значение |
|---|---|
| 🟢 | Решение **лёгкой** задачи |
| 🟡 | Решение задачи **средней** сложности |
| 🔴 | Решение **сложной** задачи |
| 🐛 | Исправление бага |
| 📝 | Обновление документации |
| 🚀 | Улучшение производительности |
| ⚡️ | Рефакторинг |
| 🎨 | Форматирование / структурные изменения |
| 🚧 | Работа в процессе |
| 🔧 | Инструменты, сборка или изменения CI |

## Сборка и запуск тестов локально

Требования: CMake ≥ 3.20 и компилятор C++23 (GCC ≥ 13 или Clang ≥ 16).

```bash
cmake -S . -B build
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

## Непрерывная интеграция

Каждый pull request проходит три проверки:

1. **Сборка и тесты** — CMake + Catch2 для `test.cpp` каждой задачи.
2. **Статический анализ** — `clang-tidy` и `cppcheck`.
3. **Проверка форматирования** — `clang-format --dry-run --Werror`.
